    What we cover

    Five modules, one continuous investigation. Every module builds on the last.

    The central question

    How do you let an agent act on real systems without giving it the keys to everything?

    Most agents today run on a long-lived token with far more access than any single task needs. When the model is tricked, confused or simply wrong, the blast radius is everything that token can reach. Safe agents need their own identity, credentials that expire in minutes and fit one tool call, and an audit trail a reviewer can actually follow. This workshop builds all three on a working agent.

    MODULE 1 · 35 min

    Agent identity and the blast radius problem

    Map what a typical agent can reach today versus what its tasks actually require. Teams score a realistic deployment and find the gap before anything goes wrong.

    • Users, agents and services as distinct principals
    • Acting on behalf of a user vs. acting as itself: delegation chains
    • Measuring blast radius: every resource a stolen token can reach
    MODULE 2 · 35 min

    Scoped credentials and vaulting

    Stop putting secrets in prompts, env vars and tool configs. Issue short-lived, narrowly scoped credentials at the moment of the tool call and keep raw secrets out of model context entirely.

    • Token exchange and downscoping for a single tool invocation
    • Vaulted secrets the model never sees, injected at execution time
    • TTLs, revocation and what happens when a credential leaks
    MODULE 3 · 30 min

    Least privilege per tool call

    Authorization decisions belong in code, not in the system prompt. Put a policy check between the model's intent and the tool's execution, and require approval for the risky ones.

    • Policy-as-code checks on tool name, arguments and resource
    • Read vs. write vs. irreversible: tiering tools by risk
    • Human approval gates for refunds, deletes and external sends
    MODULE 4 · 35 min

    Audit trails that hold up

    Log every action with enough context to answer who, on whose behalf, with what authority and why. Then replay an incident from the log alone.

    • Linking prompt, plan, tool call, credential and result in one record
    • Tamper-evident logs and what reviewers actually need
    • Detecting anomalous tool use: volume, scope and sequence
    MODULE 5 · 40 min

    The red team challenge

    Teams receive an agent wired to a ticketing system, a CRM and a payments sandbox, plus a set of injected documents. Lock it down, then attack another team's agent.

    • Redesign scopes, policies and approval gates under time pressure
    • Measure what a successful injection could reach before and after
    • Teams present their design and defend their residual risk

    Five demonstrations that produce genuine surprises

    The helpful exfiltration

    A support ticket containing hidden instructions gets the agent to email a customer list to an outside address. Nothing was hacked: the agent used permissions it legitimately held.

    The 3% token

    The agent's service account grants 214 permissions. Across 10,000 logged tasks it used 7 of them. Downscoping shrinks the blast radius by over 95% with zero failed tasks.

    The secret in the trace

    An API key passed through a tool config shows up verbatim in model context, the observability backend and a cached prompt. Vaulting at execution time removes it from all three.

    The prompt is not a policy

    A system prompt says 'never issue refunds over $500'. Three rephrasings later, the agent issues a $2,400 refund. A four-line policy check in code blocks every variant.

    The log that cannot answer

    An incident review asks who approved a deleted record. The logs show the API call but not the user, the prompt or the approval. Participants rebuild the trail with linked IDs.

    What you leave with

    Each participant or team finishes with four concrete artifacts: an agent with its own scoped identity connected to tools over MCP, a per-tool authorization policy with approval tiers, an audit log schema linking intent to action, and a threat model with measured blast radius.
